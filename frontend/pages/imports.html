CSV Format Information

New: The system now supports tab-delimited TXT files (e.g., Vision Data exports). Delimiters are automatically detected from file content.

Your CSV file for Employee Reports should include the following columns:

Column Name Description Required Example
Employee_ID Unique identifier for the employee Optional 101
Name Full name of the employee Required John Smith
Designation Job title or position Required Senior Developer
BPS Grade of the employee Optional BS-17
Office_Hierarchy Department or organizational structure Optional Technology>Development
From Start date of report period (YYYY-MM-DD) Required 2023-10-01
To End date of report period (YYYY-MM-DD) Required 2023-10-08
Tasks_Completed Description of completed tasks Required* Implemented new feature
Impact Impact of the completed tasks Optional Improved system performance
Challenges Challenges faced during the period Optional Integration issues
Support_Required Support or resources needed Optional Additional testing resources
Tasks_Planned Tasks planned for next period Optional Finalize documentation
Confidence_Level Confidence level (1-5) Optional 4
NTR Nothing to report reason Optional** On leave

* Either Tasks_Completed must be provided or NTR must be specified.
** If NTR is provided, a report will not be created.

Your CSV file for Vision Data should include the following columns:

Column Name Description Required Example
Employee_ID Unique identifier for the employee (must exist in system) Required 101
From_Date Start date of data period (YYYY-MM-DD) Required 2023-10-01
To_Date End date of data period (YYYY-MM-DD) Required 2023-10-31
Main_Entity Primary entity type being reported Required Tasks
Sub_Entities Sub-entity counts in format "Name1:Count1, Name2:Count2" Required Analysis:5, Reporting:3, Planning:2
Sub_Entities_Content Content for sub-entities as comma-separated key:list pairs Required Cases:[],Tasks:[{"id":1}]

* Employee_ID must match an existing employee in the system.
* Main_Entity should be one of: Tasks, Persons, Organizations, etc.
* Sub_Entities must follow the format "Name1:Count1, Name2:Count2" exactly.

Your CSV file for Job Descriptions should include the following columns:

Column Name Description Required Example
Employee_ID Employee identifier (must exist in system) Required 101
JD_ID Job Description identifier (numeric string) Required 1001
Job_Description Full text of the job description (min 50 characters) Required Responsible for analyzing employee performance data...
Assigned_Date Date when this JD was assigned (YYYY-MM-DD, MM/DD/YYYY, or DD/MM/YYYY) Required 2024-01-15
Is_Current Whether this is the employee's current JD (True/False, 1/0, Yes/No) Required True
End_Date Date when this JD assignment ended (leave empty if current) Optional

* Employee_ID must match an existing employee in the system.
* JD_ID is always numeric (e.g., 1001, 1002) but stored as string.
* Job_Description must be at least 50 characters long.
* If Is_Current is True, End_Date should be empty or NULL.
* Each employee can have multiple JD records tracking role changes over time.

Your CSV file for Supervisor Feedback should include the following columns:

Column Name Description Required Example
RO_Form_ID Unique identifier for the feedback form Required 5001
L_RO_Form_Metric_ID Primary key for the specific metric response Required 50001
Employee_ID Employee identifier (must exist in system) Required 101
Name Employee name (reference only, already in system) Optional John Doe
From Start date of feedback period (YYYY-MM-DD) Required 2025-11-01
To End date of feedback period (YYYY-MM-DD) Required 2025-11-30
Section_ID Section identifier (numeric) Required 1
Section Section name/category Required Performance Quality
Metric_ID Unique metric identifier (numeric) Required 101
Metric_Title Name of the evaluation metric Required Quality of Work
Instructions Explanation/description of the metric Optional Ability to deliver precise, complete, and high-quality output
Metric_Type Type of metric: "R" for rating, "T" for text Required R
Possible_Values Comma-separated rating options (NULL for text type) Conditional* Poor, Fair, Good, Excellent
Value Supervisor's rating or text feedback Required Good

* Possible_Values is required for Metric_Type="R" (rating), NULL for Metric_Type="T" (text).
* Value must match one of the options in Possible_Values for rating metrics.
* Each form (RO_Form_ID) typically has multiple rows (one per metric).
* Employee_ID must exist in the system before importing feedback.
* System automatically normalizes ratings and calculates aggregated scores.
